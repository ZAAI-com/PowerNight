# PowerNight 2.0.2 release notes

Patch release on top of [2.0.1](2.0.1.md). It restores the Tesla connection
after Tesla changed its login rules. No database migration or config changes.
Upgrade and rollback steps are the same as [2.0.0](2.0.0.md).

## Why

Tesla changed how third-party tools may log in to the owner API:

- The login page now rejects the redirect PowerNight used
  (`https://auth.tesla.com/void/callback`) with "The 'redirect_uri' supplied is
  not registered for this 'client_id'". Only `tesla://auth/callback` is accepted,
  and the token endpoint expects HTTP/2.
- Access tokens created by a token refresh are rejected with **403 Forbidden**
  when they start a new session. Only a token from a fresh login can start one.

## Fixes

- **Sign-in works again.** Settings uses `tesla://auth/callback` and exchanges
  the code through pypowerwall (HTTP/2). A browser cannot open `tesla://` links,
  so after logging in you copy that link from the browser's developer tools
  (console or Network tab) and paste it into Settings.
- **New: sign in with tokens from pypowerwall.** On a computer with a screen,
  run `pip install -U pypowerwall` and `python -m pypowerwall authtoken`, then
  paste the refresh token and access token into Settings. Paste the access token
  right away; it is valid for about 8 hours.
- **New: Sign Out of Tesla** button in Settings. It deletes the stored Tesla
  login (even when Tesla is unreachable) so you can sign in again.
- **No more 403 after a restart caused by PowerNight.** PowerNight no longer
  refreshes Tesla tokens itself, and the Dashboard and connection checks reuse
  the one long-lived Tesla session instead of opening new ones. "Retry
  Connection" no longer drops a working session. `POST /api/auth/tesla/refresh`
  was removed.
- Connection errors caused by Tesla refusing the session now say so and suggest
  signing out and in again.
- Requires pypowerwall 0.21.0 or newer.

## Known limitation

A new Tesla session still needs an access token from a fresh login. If the
container is restarted more than about 8 hours after the last sign-in, Tesla may
refuse the connection. Sign out of Tesla in Settings and sign in again.

## Upgrade from 2.0.1

Pull `zaaicom/powernight:2.0.2` (or `latest` once promoted) and restart. If
Settings shows "Tesla cloud refused the connection", click **Sign Out of Tesla**
and sign in again with one of the two methods above.
