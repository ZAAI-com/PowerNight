# PowerNight 2.1.0 release notes

Feature release on top of [2.0.2](2.0.2.md). It makes the Tesla sign-in guided
and recoverable. No database migration or config changes. Upgrade and rollback
steps are the same as [2.0.0](2.0.0.md).

## Tesla sign-in

- **Guided wizard** in Settings: Start, Sign in to Tesla, Finish connection,
  Choose site, with a 10-minute countdown.
- **No lost popups.** The Tesla tab opens immediately on click. If the browser
  blocks it, an **Open Tesla sign-in** button continues the same attempt.
- **Paste anything useful.** Pasting the `tesla://auth/callback` link, or the
  whole Console message, is checked automatically; **Verify** still works.
  Pasting the Tesla sign-in page URL by mistake explains the difference.
- **Browser-specific help** for Chrome/Edge, Safari and Firefox.
- **Survives reloads.** A reload or the app's own login screen resumes the
  attempt. If PowerNight restarted meanwhile, Settings says so and offers a
  fresh start.
- **Reconnect Tesla** replaces the stored sign-in without signing out. The
  current sign-in and live connection stay in place until the new one is
  validated and saved.
- **Explicit site choice.** A single energy site is used automatically; with
  several, you choose one. Zero sites shows guidance and a retry.
- **Honest connection state.** Settings shows Connected, Sign-in required, or
  Connection temporarily unavailable, based on what PowerNight observed. Network
  problems no longer suggest signing in again.
- **Experimental Mac helper** ([PowerNight Login](../../helpers/macos/PowerNightLogin/README.md)):
  opt-in on macOS, captures the `tesla://` link itself. Not notarized yet; the
  manual flow and token import remain available everywhere.

## Backend hardening

- Sign-in attempts are serialized: each authorization code is exchanged once,
  duplicate submissions get the current progress, and the 10-minute limit is
  enforced at every step, not only on status checks.
- Pending Tesla tokens stay on the server and are wiped on completion,
  cancellation and expiry. Tesla's error text is no longer returned or logged.
- The auth and site files are written as one unit, and the old Tesla session
  is retired under its lock so it cannot overwrite new credentials.
- New endpoints: `POST /api/auth/setup/cancel`, `POST /api/auth/setup/sites`
  and the Mac helper handoff endpoints. All setup responses carry stable
  `error_code` values next to the existing messages.
- `GET /api/auth/setup/status/<id>` now follows the same access policy as the
  other setup endpoints and gets its own rate limit for polling.

## Known limitation (unchanged)

A new Tesla session still needs an access token from a fresh sign-in. If the
container restarts more than about 8 hours after the last sign-in, Tesla may
refuse the connection; Settings then shows **Sign-in required**. Use
**Reconnect Tesla**. This release does not change that limitation.
